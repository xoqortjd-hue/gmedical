# 🎓 프로젝트 시행착오 및 개선 사항 (Lessons Learned)

이 문서는 프로젝트 개발 과정에서 발생한 주요 문제점, 실수, 그리고 이를 해결하기 위해 적용한 개선 사항들을 정리한 회고록입니다.

---

## 🚀 1. 배포 및 네트워크 환경 (Deployment & Network)

### 🔴 문제점: AWS EC2 및 터널링 서비스 불안정
- **상황**: 로컬 개발 환경에서는 잘 작동하던 웹캠 및 HTTPS 기능이 AWS 배포 후 접근 문제 발생.
- **시행착오**:
    - `Cloudflare Tunnel`: 설정 복잡도 및 간헐적 연결 끊김 발생.
    - `LocalTunnel`: 안정성 부족으로 인해 서비스가 자주 다운됨.
    - `ngrok`: 세션 만료 및 도메인 변경 문제.
- **✅ 해결책 (Improvement)**:
    - **Serveo** 도입: 별도의 설치 없이 SSH 역방향 터널링만으로 간편하게 HTTPS URL을 생성하여 안정적인 외부 접속 환경 구축.
    - **Lesson**: 배포 초기 단계에서 터널링 툴의 안정성을 테스트하고, `ssh -R` 기반의 경량화된 솔루션이 개발 테스트에 유리함을 확인.

## ⚡ 2. 모바일 성능 최적화 (Mobile Optimization)

### 🔴 문제점: 사진 데이터 로딩으로 인한 렌더링 지연
- **상황**: `MobileLendingStatusPage` (장비 현황) 접속 시, 수백 개의 아이템과 함께 Base64로 인코딩된 고용량 사진 데이터를 한 번에 불러오면서 화면이 멈추거나 로딩이 매우 느려짐.
- **원인**: 목록 조회 API (`/api/lending/items`)가 썸네일이나 메타데이터가 아닌 전체 이미지 데이터를 포함하여 응답함.
- **✅ 해결책 (Improvement)**:
    - **API 분리 전략**: 목록 조회 시에는 `photo_url` 데이터는 제외하고 `photo_exists` (사진 유무 플래그)만 반환하도록 API를 경량화.
    - **Lazy Loading**: 사용자가 "사진 보기" 버튼을 클릭할 때만 해당 아이템의 고화질 사진 데이터를 별도로 요청 (`/api/lending/items/:id/photos`) 하도록 변경.
    - **결과**: 초기 로딩 속도 수십 배 향상 및 모바일 스크롤 버벅임 해결.

## 📸 3. 사진 관리 및 업로드 로직 (Photo Management)

### 🔴 문제점: 사진 중복 및 업로드 UX 제한
- **상황**:
    1. 새 사진을 업로드해도 기존 사진이 남아있어 현황 파악이 어려움.
    2. 한 번에 한 장만 찍을 수 있어, 여러 부위를 찍어야 하는 현장 업무에 비효율적.
- **시행착오**: 단순히 `UPDATE` 쿼리만 사용하여 기존 데이터를 덮어쓰려 했으나, 다중 사진 테이블 구조에서는 불완전했음.
- **✅ 해결책 (Improvement)**:
    - **All-Delete-Then-Insert**: 업로드 시 해당 아이템의 기존 사진을 **모두 삭제** (`DELETE`) 후 새로운 사진들을 **일괄 삽입** (`INSERT`) 하는 로직으로 변경하여 데이터 무결성 확보.
    - **연속 촬영 모드 (Continuous Capture)**: 카메라 닫기 없이 연속으로 사진을 촬영하고, 메모리에 임시 저장 후 "일괄 업로드" 하는 UX 도입.
    - **Progress Feedback**: "업로드 중 (1/5)..." 와 같은 실시간 진행률 표시를 추가하여 사용자 불안감 해소.

## 🐛 4. 데이터베이스 및 스키마 설계 (Database schema)

### 🔴 문제점: 스키마 변경 대응 미흡
- **상황**: 초기에는 `lending_items` 테이블 안네 `photo_url` 컬럼 하나로 운영하려 했으나, "히스토리 관리" 및 "다중 사진" 요구사항이 생기면서 한계 봉착.
- **✅ 해결책 (Improvement)**:
    - **정규화 진행**: `lending_item_photos` 별도 테이블 생성 (1:N 관계).
    - **마이그레이션 스크립트**: 기존 데이터를 보존하면서 새 테이블 구조로 데이터를 옮기는 마이그레이션 스크립트(`migrate-photo-feature.js`) 작성 및 실행 경험 축적.

## 🗓️ 5. 시간 및 날짜 처리 (Timezone Handling)

### 🔴 문제점: 모바일 대시보드 시간 표기 오류
- **상황**: 서버(AWS/Local)와 클라이언트(Mobile Browser)의 타임존 차이로 인해, "최신 대여 현황"의 시간이 오전/오후가 뒤바뀌거나 9시간 차이가 나는 현상 발생.
- **✅ 해결책 (Improvement)**:
    - **ISO 8601 표준화**: 백엔드에서는 항상 UTC 또는 ISO 포맷으로 저장/전달.
    - **Frontend Formatting**: 클라이언트 측에서 `new Date(utcString).toLocaleString()`을 사용하여 브라우저(사용자)의 로컬 타임존에 맞춰 렌더링하도록 통일.

## 🖨️ 6. QR 코드 일괄 출력 (UX/Process)

### 🔴 문제점: 개별 출력의 비효율성
- **상황**: 장비 등록 후 QR 코드를 하나씩 출력해야 해서 용지 낭비가 심함.
- **✅ 해결책 (Improvement)**:
    - **Print Queue 시스템**: 출력할 아이템을 "대기열"에 담아두고, A4 용지 한 장이 꽉 찼을 때 일괄 출력하는 기능 구현.
    - **자동 그룹화**: Big/Medium/Mini 사이즈별로 자동 정렬하여 출력 레이아웃 최적화.

## 📝 7. 기타 UI/UX 개선 (Miscellaneous)

- **비고/수리 팝업**: 좁은 모바일 화면에 긴 텍스트를 구겨 넣지 않고, 별도 버튼과 팝업을 통해 상세 내용을 확인하도록 개선.
- **입고(Inbound) 페이지 개선**: 바코드 스캔 시 등록/미등록 제품 자동 판별 및 신규 등록 유도 워크플로우 정립.
